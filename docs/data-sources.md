# Data sources

English | [한국어](ko/data-sources.md)

The databases Qurry works with, how to connect to them (SSH, AWS SSM, SSL, options) and how drivers for the less common ones are added.

## Supported databases

| Database | Features |
|---|---|
| PostgreSQL | Explorer tree (databases, schemas, tables, views, sequences, routines), query console (server-side cursor paging, cancel, manual transactions), data editing, explain plan, DDL, full-text search. `infinity` / `-infinity` dates and timestamps show as such, and arrays of them show their values |
| MySQL / MariaDB | Same as above. A MySQL database is its own schema, so tables appear directly under the database |
| Redis | Medis-style browser (key list with type and TTL, per-type value editor), redis-cli style terminal, **Standalone / Sentinel / Cluster** |

Connection options:
- **SSH tunnel** with a key or password. Host keys are checked against `~/.ssh/known_hosts`: a changed key is refused, and an unknown server stops with its SHA256 fingerprint until you choose **Trust host key** (GUI: data source dialog; TUI: `⌃y` in the form or `⌃k › Trust SSH Host Key`). The tunnel listens on a random port on `127.0.0.1` while the data source is connected; other programs on the same computer could use that port too, so on a shared machine use database passwords (not only the bastion's IP allow-list) and set **Auto-disconnect** so idle tunnels close. One SSH session serves all databases of the data source; when it ends (the laptop sleeps, the network changes), the next query logs in again.
- **AWS SSM tunnel** (Session Manager port forwarding), the other choice next to SSH: GUI **SSH/SSL** tab › **Tunnel** › *AWS SSM*; TUI `Tunnel` › `aws ssm`. Enter the **AWS profile** and **region** (empty = the AWS CLI's defaults) and the **instance id** (`i-…`, or `mi-…` for a managed node); the data source's Host / Port (GUI: General tab) are the database as seen from that instance, not a port on your computer: for an RDS database behind a bastion, Host `mydb.cluster-abc.ap-northeast-2.rds.amazonaws.com` and Port `5432`. `localhost` / `127.0.0.1` is the instance itself (`::1` isn't accepted: use `127.0.0.1`); the form says so in a hint, and that is right only when the database runs on the instance. When the instance can't reach Host:Port, connecting fails with "AWS SSM: the instance couldn't reach …". Qurry runs `aws ssm start-session --document-name AWS-StartPortForwardingSessionToRemoteHost` on a random `127.0.0.1` port, waits until the plugin says it opened that port (up to 30 seconds), and connects through it. One session serves all databases of the data source. Qurry closes its sessions: when the data source disconnects, when a session doesn't open in time, and when the app quits, crashes or is stopped, it ends the session on the AWS side (`aws ssm terminate-session` with the same profile and region, on quit all at once: Qurry waits up to 2 seconds and lets slower ones finish on their own) and stops the CLI and its plugin. Stopping the CLI alone would leave the session open on the instance, and an instance with many open sessions stops opening new ones: the error then says the session started but its data channel didn't open (such sessions time out on their own). Ending sessions needs `ssm:TerminateSession` on your own sessions (without it, the CLI and plugin are still stopped); when the session ends by itself (Session Manager's idle timeout, a network drop), the next query opens a new one. Without an instance id, connecting fails and asks for it (it never connects to the host directly). Qurry stores no AWS secrets: the AWS CLI signs in with your own `~/.aws/config`, SSO login or environment. You need [AWS CLI v2](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) and the Session Manager plugin (macOS: `brew install --cask session-manager-plugin`); the error says which one is missing. When your SSO session has expired, the error says what to run, for example `aws sso login --profile prod`. Your AWS identity needs `ssm:StartSession` on the instance and on the `AWS-StartPortForwardingSessionToRemoteHost` document, and the instance's SSM agent must be online. Several connections at once need plugin 1.2.x or later. The same note about other programs on this computer as for SSH applies to the local port. In the GUI, **Test Connection** on that tab starts a session and connects to the database (TUI: ⌃t); while it runs it shows the elapsed time, and **Cancel Test** (or Esc; TUI: ⌃t or Esc) stops it and the session. Choosing another Tunnel stops it too. A long error, such as a missing plugin with its install link, scrolls into view so you can read what to do. If the data source is disconnected or saved while a database is still connecting, that database says "The data source was disconnected while connecting. Run it again." and never keeps a connection to the closed session's port; run it again to open a new session. When several tabs or the tree open the data source at the same time and the session can't be started, they all show that one error instead of trying again one after another. A database that is missing or refused fails only where it was opened: the session stays open for the others. **Update every Qurry app on this computer first** (the GUI, and the TUI and MCP server with `brew upgrade qurry` or ⌃k › Update Qurry & Restart): older versions don't know AWS SSM and would connect to the host directly. So they never get the saved password of an SSM data source (their connection fails without it), and when they save the data sources, the SSM settings are kept for the updated apps.
- **SSL/TLS**: Require / Verify CA / Full Verification, with optional CA and client certificate. Works for PostgreSQL, MySQL and Redis. Turning SSL on starts at **Require** (shown as "encrypt, no certificate check"), which only encrypts and doesn't check the certificate, so it doesn't protect against someone in the middle posing as the server. **Full Verification** (certificate and host name) does — for a server with a private CA, together with its CA file (see below); Verify CA checks the certificate but not the host name. For PostgreSQL and MySQL, verification uses a built-in list of public CAs (not the system's trust store), so a server with a certificate from AWS RDS, a company CA or a self-signed one needs its CA file; Redis uses the system's trust store. With SSL off, a remote PostgreSQL or MySQL server must still set up TLS (the certificate isn't checked) or Qurry doesn't send the password — the same goes for backup and restore. For a server without TLS (or an old MySQL 5.7 without TLS 1.2) on a network you trust, tick **Allow unencrypted connection** in Options (TUI: `Allow unencrypted` in the data source form); Test Connection and the status bar then say "Not encrypted". When a connection fails for this reason, the error offers it in one click: **Allow unencrypted for this data source** under the explorer, console or table tab error (TUI: a confirm popup that names the data source and only `y` answers — not Enter, and only after a pause: it can appear while you are still typing, and each key typed into it starts the wait again; if another popup was open, the status line says so instead, and expanding the data source again (`←` `→`) or running again asks). It turns the setting on for that data source only and keeps its saved password; the tree then loads again and a table tab reloads, while a console only reconnects ("Connected. Run again.") and never runs the statement again; a tree still showing the error loads again too. In Data Source Properties, a failed Test Connection offers the same button, which ticks the checkbox in the form and tests again (it is saved with OK; TUI: a failed `⌃t` selects the form's `Allow unencrypted` field, `Space` turns it on and `⌃t` tests again, saved with Enter). It is never offered for **Production** data sources: the message says where the setting is, and you turn it on yourself in the form. To undo, turn off **Options ▸ Allow unencrypted connection** (TUI: `Allow unencrypted` in the data source form, `e` in the explorer). Servers on this computer (including a PostgreSQL Unix socket: a host such as `/var/run/postgresql`) and connections through an SSH or AWS SSM tunnel never need TLS. Backup and restore with MariaDB's `mysql` / `mysqldump` use its `--ssl` options; when both are installed, the MySQL client is used.
- **Options tab**: read-only, transaction control and isolation level, time zone, keep-alive, auto-disconnect when idle, single database mode, startup script.
- **Production**: before a statement that changes data runs, Qurry counts the rows it will change (the same table and WHERE as a `SELECT count(*)`, nothing is changed) and asks. Statements it can't count (`UPDATE … FROM`, `DELETE … USING`, CTEs) still ask; statements that change the structure (DDL) show as "schema change". Reads run without asking, also when a write word appears only in a string or a comment (`select 'delete' as action`, MySQL `# delete …`); a quoted name such as `"update"` still asks. With a backslash in a string, where the string ends depends on a server setting (MySQL `NO_BACKSLASH_ESCAPES` and `ANSI_QUOTES`, PostgreSQL `standard_conforming_strings`), so Qurry asks if the statement would change data under any of them. A call to a function with side effects (`dblink_exec`, `setval`, `set_config`, `pg_sleep`, MySQL `get_lock` …) also asks, since the write can be hidden in a string it runs, and so do sequence and large-object writers (`nextval`, `lo_unlink` …) and `SELECT … INTO` (a new table, a file on the MySQL server, or MySQL `@variables`). A selection run as one statement (Query Execution Settings › For selection execute › Exactly as a single statement) goes to the server as one text, so it asks if any statement in it changes data (`select 1; do $$ … delete … $$`, MySQL `select 1; prepare s from '…'; execute s`). The GUI and the TUI decide this the same way. GUI: Options tab · TUI: the `Production` toggle in the data source form.
- **MCP**: what AI tools may do through `qurry-mcp` — Off (new data sources; not listed, never connected), Read, or Read & write (with `--allow-write`). See [MCP server](mcp.md). GUI: Options tab · TUI: the `MCP` field.

> Redis Sentinel and Cluster nodes advertise their own addresses, so they can't be combined with an SSH or AWS SSM tunnel.

## Drivers (added when you need them)

Nothing extra is installed up front. Pick one of these types for a data source and Qurry offers to **Install** its driver: a small program downloaded from the GitHub release of your Qurry version, checked against the signed `SHA256SUMS` (same key as app updates) and kept in the config folder under `drivers/`.

| Database | Notes |
|---|---|
| SQL Server | SQL Server 2017+ (older versions work, with a warning); `dbo` and other schemas |
| Oracle | Needs the free [Oracle Instant Client](https://www.oracle.com/database/technologies/instant-client.html) — set its folder in the data source (or `ORACLE_CLIENT_LIB_DIR`). Oracle 19c+ (11g works, with a warning); the service name goes in Database |
| SQLite · DuckDB | A file instead of host and port (DuckDB: empty = in memory) |
| ClickHouse | Over HTTP (port 8123) |
| MongoDB | Shell syntax in the console: `db.users.find({age: {$gt: 30}}).sort({age: -1}).limit(10)`, `aggregate`, `countDocuments`, `insertMany`, `updateMany` …, or a command as JSON. Fields are guessed from 50 documents |
| Qdrant · Chroma · Milvus | Collections are tables. The console takes REST requests — see [Vector databases](vector-and-rag.md) |

The data source test shows the server version and warns when it is older than the versions Qurry is tested with (PostgreSQL 12, MySQL 5.7, MariaDB 10.5, SQL Server 2017, MongoDB 5, ClickHouse 22, Oracle 19c — CI runs against these). Read-only data sources are enforced for drivers too: MongoDB runs only `find` / `aggregate` (without `$out` / `$merge`) / `count` / `distinct`, vector databases only `GET` and search requests.

Each data source can have a color that tints its tree and marks its tabs (handy for telling production apart). Besides the presets, the rainbow swatch opens the system color picker — on macOS its eyedropper picks any pixel on screen, e.g. the color you used in DataGrip — or type a hex value next to it. The TUI cycles through the presets and keeps a custom color as is.

The active tab stands out: it takes the editor's background (a colored data source's tab its full color), bold text and an accent bar (gray in a split pane that doesn't have focus); the other tabs keep the stripe and a fainter tint. Tabs, the Switcher, Recent Files and Search Everywhere show the same icon as the object's row in the explorer, and a DDL tab adds a small DDL mark to its object's icon (a DDL tab saved by an older version shows the generic DDL icon until it is reopened). The TUI uses the tree's glyphs in the tab bar, Recent Tabs (`⌃e`) and the `⌃p` search, with `≡` after a DDL tab's glyph; for how its active tab looks, see [TUI in your terminal](tui.md#colors).
