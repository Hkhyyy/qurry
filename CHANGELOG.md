# Changelog

What changed in each Qurry version, for people who use it. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Betas (`vX.Y.Z-beta.N`) are listed under the stable version they lead to. Versions up to 0.2.x are listed only on [GitHub Releases](https://github.com/Hkhyyy/qurry/releases).

## [Unreleased]

### Added

- **TUI: connect from a URL** without saving a data source, for on-call work: `qurry-tui postgres://user@host/db`, `mysql://…`, `redis://…`, `rediss://…` (TLS), or `--env` for `DATABASE_URL`. Missing parts come from `PGHOST` / `PGPORT` / `PGUSER` / `PGDATABASE` / `PGPASSWORD` / `PGSSLMODE` and `~/.pgpass` (only when it is `chmod 600`), `MYSQL_PWD` or `REDISCLI_AUTH`. The temporary data source is never saved, never shared with the GUI or MCP, and its password never shows in names, errors or history. `--read-only` refuses writes as a Read-only data source does, `--incident` opens Database Admin › Sessions, `--ssh DEST` goes through an SSH tunnel. A URL's certificate files are never skipped (`sslrootcert` / `ssl-ca` without a mode checks the server, a mode that wouldn't use them is refused), and a password in the URL is warned about only when it is on the command line. Unknown schemes, parameters and options stop with what is wrong (#59, [TUI in your terminal](docs/tui.md#connect-from-a-url)).
- **SSH tunnels use ssh-agent and `~/.ssh/config`** (GUI, TUI, MCP): leave the private key (or password) empty to log in with ssh-agent, then the `IdentityFile` keys; an SSH host can be a `Host` alias with `HostName`, `User`, `Port`, `IdentityFile`, `IdentityAgent` and `ProxyJump` chains. `IdentitiesOnly` is honored, and the agent offers the `IdentityFile`'s key first. `ProxyCommand` isn't run (except `ssh -W %h:%p jump`) (#59, [Data sources](docs/data-sources.md)).
- **Import Data Sources from DataGrip / IntelliJ and DBeaver**: explorer ⋮ › Import Data Sources ▸ (and Find Action; TUI `⌃k` › Import Data Sources…) lists the locations found on this computer (IDE global settings, DataGrip and recent IDE projects, DBeaver workspaces), or reads a file or folder you pick. The connection, SSH tunnel, SSL and Read-only settings are mapped; the confirm shows one row per data source, with a checkbox to leave it out, and lists the kinds Qurry doesn't support and the ones it already has as skipped with the reason. New data sources start with MCP Off; passwords are never imported and are asked on the first connect. The TUI imports Qurry's own export too (#63, [Data sources](docs/data-sources.md#export-and-import)).

### Changed

- **A saved SSH host with a `Host` block in `~/.ssh/config` uses it**, as `ssh` does: its `HostName`, `ProxyJump`, `IdentityFile`, and `User` / `Port` when the data source leaves them empty / at 22. A `ProxyCommand` there now stops the connect, naming the file, line and `Host` block, with what to do (use `ProxyJump`, or `ProxyCommand none` in a narrower `Host` block above it). **A `ProxyCommand` under `Host *` stops every SSH tunnel it matches**, including data sources with their own key or password: add `Host <your-bastion>` / `ProxyCommand none` above it. An `IdentityFile` with a `%` token Qurry doesn't know (`%C`, `%n`, …) is skipped, not an error (#59).
- **PostgreSQL `~/.pgpass`** is matched against the data source's own host, port, database and user (it used to be matched against `PGHOST` / localhost) and is read only when no one else can read it (`chmod 600 ~/.pgpass`), as `psql` does; when it was skipped and the login fails, the error says why. **`PGSSLMODE` no longer overrides a data source's TLS mode** (a local or tunneled PostgreSQL source without SSL settings uses prefer, a remote one require, as the data source says). **`PGPASSWORD` is no longer sent to saved PostgreSQL data sources** without a saved password (GUI, TUI, MCP): an environment password goes only to a `qurry-tui` URL's server. If you relied on it, save the password in the data source or add a `~/.pgpass` line; the login error says so (#59).

## [0.3.1] - 2026-11-04

### Added

- **Edit console results**: a console result from one table that includes the table's whole primary key edits like a table tab, in the GUI and the TUI: the same Submit path (each `UPDATE` / `DELETE` must hit exactly one row, read-only data sources, Production log), SQL written with the table's column names behind aliases. Joins, `GROUP BY`, `DISTINCT`, `UNION`, computed columns, views and results without the key stay read-only, and the greyed-out buttons (TUI: the status line) say why. Results of a temporary table or a locking read (`FOR UPDATE` / `FOR SHARE`, `LOCK IN SHARE MODE`), and every console result in Manual mode or while a transaction is open, stay read-only with the reason, because the edits are saved on a connection of their own. Running the console again with pending edits asks first (#86, [Getting started](docs/getting-started.md)).
- **Multi-select in the result grid**: ⌘-click adds a cell, a row (row number) or a column (header) to the selection, ⇧-click extends the last range; copy, the Data Extractor, Delete Row, Revert Selected and Set NULL act on every range. TUI: `m` marks the current row, `y` / `d` / `Y` act on the marked rows (#96).
- **Multi-select in the Database Explorer**: ⌘-click and ⇧-click select several nodes; Go to DDL, Edit Data, Copy Name / Reference, Refresh and **Drop…** (one confirmation, the Production one on Production sources) act on all of them. TUI: `m` marks nodes, Delete drops the marked objects. On MySQL, Drop… of several objects runs one statement per object, dependents first (a table before the tables it references), and a failure reports what was applied, what failed and what didn't run (#96, [Shortcuts](docs/shortcuts-gui.md)).
- **Console gutter marks**: each statement that ran is marked on its first line: ✓ done, ✗ failed, a spinner (TUI `…`) while it runs. Hover shows when it ran and its result or error; a click shows its line in Output. Only the latest run is marked: a new run clears the earlier marks, and editing the statement drops its mark (#98).
- **Completion in the table filter**: a table tab's WHERE / ORDER BY field completes like the console with the table's columns, keywords and functions (no other tables or schemas), as you type or with ⌃Space (TUI ⇥) (#93).
- **TUI light theme**: a light palette for light terminals and **⌃k › Theme…** (Auto, Dark, Light, saved in `settings.json`). Auto follows `COLORFGBG` and says at startup how to get the dark colors back (#90, [TUI in your terminal](docs/tui.md)).
- **Database Admin reports: pick the database** in the report toolbar (TUI: `d`) to rerun the report on it; like the console's database picker it lists every database of the server, the current one first (Manage Shown Schemas only filters the explorer). A connect error names the database and suggests picking another one only when the server refuses that database (#99, [Database tools](docs/database-tools.md)).
- **Add Font File…** in GUI **Settings › Editor / Grid font**: pick a `.ttf`, `.otf`, `.woff` or `.woff2` (up to 20 MB); Qurry copies it into its config folder and lists it as an added font you can remove. The TUI keeps the terminal's font (#87, [Settings](docs/settings.md)).

### Changed

- **`NULL` sits where its column's type does** in result grids (GUI and TUI): on the left in text, date / time, boolean and JSON columns, on the right in numeric ones; in a column without a type (a SQLite expression, MongoDB) it goes by the column's values. It is the new **Column type** choice for NULL in **Settings › Appearance › Alignment** (TUI **⌃k › Grid Alignment…**), and the default. A NULL alignment you saved as Left or Center stays as it was. If you kept the 0.3.0 default, `NULL`s in text-like columns move to the left: to keep the 0.3.0 look, set **NULL** to **Right** (#95, [Settings](docs/settings.md)).
- **⌘-click adds to the selection** in the result grid and the Database Explorer (it used to select only the clicked cell or node) (#96).
- **Submit on a Production data source asks first**, in table tabs as well as consoles: the dialog lists the statements; Cancel keeps the pending edits (#86).
- **Settings and Keymap Reference buttons** moved from the right end of the status bar to the bottom of the workspace rail on the far left; the workspace list scrolls above them. ⌘, and ⇧⌘/ still work. In maximized mode (tool windows hidden) there are no mouse buttons for them: use ⌘, / ⇧⌘/ or the Help menu (#97).
- **TUI Auto theme follows `COLORFGBG`**: on a terminal that reports a light background the TUI now draws its light palette. To keep the dark colors, pick **⌃k › Theme… › Dark** (#90).
- Console line numbers move to the right to make room for the gutter marks (#98).
- The running indicator moved from a card over the result to the status bar; ■ cancels runs and load-more (the card's Cancel button is gone). Loading more rows shows there too, as a run does ("Loading more rows…" with the elapsed time), so nothing covers the grid's rows; a load-more that fails says why beside the row count with **Run again**. TUI: the status line shows a moving bar, what runs or loads and the elapsed time, and the Cancel key stops a load-more too (#94).
- Release builds are faster: e2e runs one job per browser with two Playwright workers, and the release builds the CLI in its own job (#88).
- [SECURITY.md](SECURITY.md) describes the release signing key: where it lives, how it is rotated through a bridge release, and what happens when it is lost or leaked (#91).

### Fixed

- The database pickers of consoles, Redis browsers and Database Admin reports (and the console's schema picker) list their databases as soon as the tab is shown: the first click used to open a list with only the current database, the rest arriving too late.
- Console completion no longer offers column values in a JOIN's `ON` condition (`on m.admin_user_idx = `), where the other side is usually a column: the statement's columns complete there; a `WHERE` after the join still suggests values.
- Database Admin reports: picking a database the account can't connect to no longer makes the database list as wide as the window or empties it. The listing error shows above the report (and as the list's tooltip) instead of as a list entry, and the list is read through the source's default database when the report's refuses, so another one can be picked (TUI `d` likewise). Long database names are cut with … in the report's and the console's lists.
- **Statements popup** (⌘↩ with several choices; TUI F5): while a choice is highlighted the editor highlights exactly what it would run (TUI: its rows; the TUI chooser sits at the bottom so they stay in view), and the highlight goes when the popup closes. The GUI popup now has the keys like a menu: ↑↓ and Enter pick, Esc or any other key closes it without running and without typing into the editor, a click outside or focus leaving closes it, and the caret is where it was.
- **New Query Console** (⇧⌘L) and the other commands that act on the explorer selection use the shown workspace's selection: back from a workspace with a Redis source selected, a new console used to open for that Redis source, and every new console after it.
- Console Output keeps its newest line in view while following: new lines, long wrapped lines (TUI) and a pane made shorter or narrower (#92).
- **Manage Shown Schemas**: with **All databases** or **All schemas** on, unchecking one database or schema used to do nothing until All was unchecked first. Now All turns off and the other listed ones stay shown (a database keeps its schema choice; system schemas and MySQL's system databases stay hidden unless checked one by one); checking every one again turns All back on (GUI and TUI, as in DataGrip). The Schemas tab of Data Source Properties follows the same rules: under All, every database and schema shows checked.

## [0.3.0] - 2026-11-04

### Added

- Stable and beta update channels. Stable (the default) gets the releases made from a version tag; beta also gets the pre-release built from every merge to `main`. Pick one in GUI **Settings › Appearance › Updates** or TUI **⌃k › Update Channel…**; the GUI, the TUI and `qurry-tui --update` share it. See [Updates](docs/updates.md).
- **TUI color modes**: `NO_COLOR` draws without colors (reverse video for selections and badges, bold edited cells, `+` `-` `~` in the row number) and says how to get them back; 256- and 16-color terminals get the nearest palette colors; kitty, Alacritty, WezTerm, foot and Ghostty get true color without `COLORTERM`. A window smaller than 40×10 shows "terminal too small" instead of crashing, and only the quit key acts there. See [TUI in your terminal](docs/tui.md).
- **Allow unencrypted in one click**: when a remote PostgreSQL or MySQL server without TLS refuses the connection, the error in the explorer, console, table tab or Test Connection offers **Allow unencrypted for this data source** (TUI: a confirm popup that only `y` answers). It keeps the saved password, and is never offered for Production data sources ([Data sources](docs/data-sources.md)).
- **AWS SSM tunnel**: connect through Session Manager port forwarding (GUI **SSH/SSL › Tunnel › AWS SSM**, TUI `Tunnel` › `aws ssm`) with your AWS profile, region and instance id. Qurry runs the AWS CLI v2 and its Session Manager plugin and stores no AWS secrets. Host and Port are the database as seen from the instance (the form hints when they point at the instance itself); Qurry ends its sessions on the AWS side when it closes them. Update every Qurry app on the computer first: older ones don't know the tunnel ([Data sources](docs/data-sources.md)).
- [SECURITY.md](SECURITY.md) (report a vulnerability privately through GitHub), [CONTRIBUTING.md](CONTRIBUTING.md) (toolchain, tests, commit and language rules, issue and pull request templates) and the [MCP threat model](docs/mcp-security.md): what an AI client reaches for each MCP setting, how read-only is enforced, and what Qurry does not protect against.
- This changelog.
- **Alignment in result grids**: GUI **Settings › Appearance › Alignment** sets Left, Center or Right for each kind of value (string, number, date / time, boolean, NULL, JSON / binary). The TUI grid uses the same kinds and the same setting (`settings.json`), changed there with **⌃k › Grid Alignment…** (#75, [Settings](docs/settings.md)).

### Changed

- **`NULL` is right-aligned** in result grids (GUI and TUI), so a `NULL` in a numeric column lines up with its numbers. To have it on the left as before, set **Settings › Appearance › Alignment › NULL** to **Left**. Numbers the driver sends as text (`numeric`, large `bigint`) are now right-aligned in the GUI too, as the TUI did (#75).

- **Releases**: a merge to `main` now publishes a beta pre-release (`vX.Y.Z-beta.N`). Stable releases come only from a version tag on `main`, and only they update Homebrew. Only the 20 newest betas keep their release page: an older beta can't install driver plugins any more and says to update Qurry. A beta `.deb` has the package version `X.Y.Z~beta.N`, so `apt` takes the stable `X.Y.Z` as an upgrade.
- **macOS 13 Ventura or later** is needed for the GUI. On macOS 12 or older keep Qurry 0.2.x; the TUI and the MCP server still run there ([what to do if an update already went through](docs/updates.md#macos-12-and-older)).
- The GUI and the TUI share one Rust core for statement splitting, the Production guard, completion, grid copy formats, charts and the keymap. The GUI runs it as WebAssembly, so its Content Security Policy allows `wasm-unsafe-eval`.
- The GUI Production confirmation decides like the TUI: a keyword inside a string, a quoted name or a MySQL `#` comment no longer asks. Settings under which a statement could write, side-effect functions (`nextval`, `setval`, `dblink_exec`, `lo_*`) and `SELECT … INTO` now ask. A selection run as one statement is a read only if every statement in it is (`select 1; do $$ … delete … $$` asks), and so is SQL Server text that starts another statement without `;`.
- **Explain Analyze** asks first when a rollback can't undo what the statement does (sequence values, `dblink_exec`, `SELECT … INTO OUTFILE`, a `COMMIT` or MySQL DDL after the first statement): Cancel runs nothing, and Output says afterwards what stays. On data sources other than PostgreSQL and MySQL it isn't wrapped in a transaction and asks "it changes data". GUI and TUI decide the same way ([Safety](docs/safety.md)).
- GUI console: while the WebAssembly module loads, `⌘↩` shows a loading bar and runs once it arrives. Without the module, a notice says once when a console opens that autocomplete is off.
- PostgreSQL strings with a backslash are written as `E'…'` in grid copy formats, **Filter by** and the SQL of grid edits (they used to write `'a\b'`), and MySQL value hints double backslashes. ClickHouse names in the grid's SQL double a backslash inside the quotes, as the server reads them.
- Errors for operations a driver plugin doesn't support read "<op> isn't available for the <driver> driver".
- **Explain Analyze** on PostgreSQL and MySQL rolls back every statement, reads included (a function a `SELECT` calls could write), and asks first before an `UPDATE` or `DELETE` without `WHERE` (every row stays locked until the rollback). Inside an open transaction (on MySQL also one Qurry didn't see open, such as a `START TRANSACTION` inside a `/*! … */` comment), or on MySQL with autocommit off however it was switched off, it uses a savepoint, so it never commits work you left uncommitted. It asks that one question instead of the "dangerous statement" question as well, in the GUI as in the TUI. On a read-only data source it works inside a transaction you opened.
- Contributors need the `wasm32-unknown-unknown` target and `wasm-bindgen-cli` 0.2.129 ([Development](docs/development.md)).

### Fixed

- GUI result grid, table data editor and transposed view: rows no longer show through a strip between the toolbar and the column header in a short result panel on macOS (#82).
- PostgreSQL nested comments and MySQL `#` comments split the way the server reads them, so a commented-out statement never runs.
- Full-text search runs each table's `SELECT` in a READ ONLY transaction on PostgreSQL and MySQL, so a view whose function writes (an `INSERT`, `nextval`) is refused instead of committed.
- Console completion: quoted names with spaces before the dot, `from sales.` with a table named `sales`, Korean identifiers, and long scripts stay fast.
- Korean names rank like their ASCII twins in the TUI palette and MCP `search_objects`; Redis key folders stop at 64 levels.
- Database Admin reports on managed services, MariaDB and large servers (#64); a failed refresh keeps the last result and says how old it is.
- MySQL backup and restore: the client that matches the server's kind and version, `--set-gtid-purged=OFF`, optional removal of `DEFINER=` clauses, and shell commands off during a restore.
- Production log: a change is logged before it runs, and undo SQL is kept only when every changed row was saved.
- PostgreSQL full-text search and value hints write a search text or value with a backslash as `E'…'`, so a server with `standard_conforming_strings = off` can't read it as SQL.
- SQL Server: a `SELECT` of columns named `open`, `close` and the like is a read again (no Production confirmation).
- TUI: the Explain Analyze note about what a rollback can't undo is a warning, not an error.
