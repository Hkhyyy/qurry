# Changelog

What changed in each Qurry version, for people who use it. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Betas (`vX.Y.Z-beta.N`) are listed under the stable version they lead to. Versions up to 0.2.x are listed only on [GitHub Releases](https://github.com/Hkhyyy/qurry/releases).

## [Unreleased]

### Added

- **Stronger console completion** (#105, #62), one engine for the GUI and the TUI: completion follows the scope at the caret (CTEs and their columns, subquery and nested-select aliases, `USING` / `NATURAL` joins); after `join <table>` it offers the whole `ON` condition from the foreign keys, and after `join` the tables related by one come first; `group by` lists the select list's non-aggregated expressions, `order by` its aliases first, `insert into t (…)` the columns not used yet; templates `sel`, `ins`, `upd`, `del`; `⌃Space` after `*` expands it into the column list; built-in and user functions with their signatures, and signature help inside a call's parentheses (TUI: a hint line); a table or column the statement's scope lacks is underlined, and `⌥↩` on it offers the closest names (no marks for CTEs, aliases, functions or databases not loaded). Completion metadata now reads foreign keys and user functions. See [Console completion](docs/database-tools.md#console-completion-postgresql-mysql).
- **TUI: connect from a URL** without saving a data source, for on-call work: `qurry-tui postgres://user@host/db`, `mysql://…`, `redis://…`, `rediss://…` (TLS), or `--env` for `DATABASE_URL`. Missing parts come from `PGHOST` / `PGPORT` / `PGUSER` / `PGDATABASE` / `PGPASSWORD` / `PGSSLMODE` and `~/.pgpass` (only when it is `chmod 600`), `MYSQL_PWD` or `REDISCLI_AUTH`. The temporary data source is never saved, never shared with the GUI or MCP, and its password never shows in names, errors or history. `--read-only` refuses writes as a Read-only data source does, `--incident` opens Database Admin › Sessions, `--ssh DEST` goes through an SSH tunnel. A URL's certificate files are never skipped (`sslrootcert` / `ssl-ca` without a mode checks the server, a mode that wouldn't use them is refused), and a password in the URL is warned about only when it is on the command line. Unknown schemes, parameters and options stop with what is wrong (#59, [TUI in your terminal](docs/tui.md#connect-from-a-url)).
- **SSH tunnels use ssh-agent and `~/.ssh/config`** (GUI, TUI, MCP): leave the private key (or password) empty to log in with ssh-agent, then the `IdentityFile` keys; an SSH host can be a `Host` alias with `HostName`, `User`, `Port`, `IdentityFile`, `IdentityAgent` and `ProxyJump` chains. `IdentitiesOnly` is honored, and the agent offers the `IdentityFile`'s key first. `ProxyCommand` isn't run (except `ssh -W %h:%p jump`) (#59, [Data sources](docs/data-sources.md)).
- **Import Data Sources from DataGrip / IntelliJ and DBeaver**: explorer ⋮ or + › Import Data Sources ▸, or the link in an empty explorer (and Find Action; TUI `⌃k` › Import Data Sources…) lists the locations found on this computer (IDE global settings, DataGrip and recent IDE projects, DBeaver workspaces), or reads a file or folder you pick. The connection, SSH tunnel, SSL and Read-only settings are mapped; the confirm shows one row per data source, with a checkbox to leave it out, and lists the kinds Qurry doesn't support and the ones it already has as skipped with the reason. New data sources start with MCP Off; passwords are never imported and are asked on the first connect. The TUI imports Qurry's own export too (#63, [Data sources](docs/data-sources.md#export-and-import)).
- **Resize result grid columns**: drag a column header's right edge, double-click it to fit the column to the rows loaded so far (again: back to the width before), or right-click a header for Fit Column, Fit All Columns and Reset Widths; `⌃⌥←` / `⌃⌥→` narrow / widen the current column (bindable). TUI: `<` / `>` narrow / widen, `=` fits, ⌃k › Fit All Columns / Reset Column Widths. A table tab remembers its widths per table in `settings.json`, shared by the GUI and the TUI; a console result keeps them until it runs again. Columns keep their computed widths until you resize them, and Reset Widths goes back to those. Fit counts a wide character (Hangul, CJK, emoji) as 2 in both apps, and a join's columns with the same name resize on their own (#109, [Settings](docs/settings.md#column-widths-in-result-grids)).
- **More themes, and custom themes** (#103, GUI and TUI): **Dracula**, **One Dark**, **Solarized Dark** and **Solarized Light** next to Dark, Light and High contrast. Each colors the panels, the editor (SQL and JSON), the result grid's edited, added and deleted rows, find matches and NULLs, the Data Source tints and the Production stripe, and the TUI (truecolor, 256 and 16 colors; `NO_COLOR` stays monochrome). Every built-in theme keeps text at 4.5:1 and dim text, NULLs, icons and the accent at 3:1 on each surface they are drawn on (editor, current line, panels, odd grid rows, hover, selection, Production tint), adjusting a published color in its own hue where it fell short. **Settings › Appearance › Theme › Edit Colors…** makes a custom theme from any theme: basic and advanced colors with a picker and the hex, the whole window as the live preview plus a preview of every state, the place a color is used outlined when you point at its name, and contrast warnings that are shown, never fixed for you; changing Based on or importing over unsaved colors asks first, and Save keeps Sync with OS on. **Import… / Export…** a theme as a small JSON file (anything but known colors as `#rrggbb` is refused, with why). **Sync with OS** picks a dark and a light theme of your choice. Settings, Quick Switch Theme (`` ⌃` ``), Find Action and the TUI's **⌃k › Theme…** list the built-in and custom themes ([Settings › Themes](docs/settings.md#themes), [TUI › Themes](docs/tui.md#themes)).
- **Quotes and brackets pair up outside the console too** (#105): a table tab's WHERE / ORDER BY fields and the TUI console and its `w` / `o` inputs close `'` `"` `(` `[` as you type, step over the closing one, remove an empty pair with `⌫` and wrap a selection, as the GUI console does — but never inside a string or a comment. **An unclosed quote, parenthesis or bracket is marked** in the console (GUI: a red underline to the end of its line, with what is open on hover; TUI: the character and its line number in red, and what is open on the editor's bottom border), reading strings, comments and dollar quotes as the statement splitter does ([Database tools](docs/database-tools.md#quotes-and-brackets)).
- **Run a subquery** (#105, GUI and TUI): with the caret inside a subquery, a CTE body or `in (select …)`, `⌘↩` (TUI `F5`) also offers it after the whole statement, innermost first as in DataGrip; the editor highlights exactly what each choice runs and only that runs, through the same read-only, Production and dangerous-statement checks. The whole statement stays the first choice
- **Server errors marked in the console** (#105, GUI and TUI): a failed statement's error shows in the editor where the server points (PostgreSQL's position, MySQL's line and `near '…'`), else over the statement; the GUI's hover has the message, the TUI underlines it and its status line says where. Fix the statement and run it again: an edit or the next run clears the mark, and Output keeps the error. PostgreSQL errors in Output now end with `(position N)`
- **Keyword case** (#105, GUI and TUI): **Settings › Appearance › Keyword case** (TUI **⌃k › Keyword Case…**), shared in `settings.json`, sets SQL keywords to **UPPER** or **lower** as you type in a console (after a space, a new line or punctuation; not in strings, comments, quoted names or a name next to a dot such as `t.order`, and never words tables often use as columns such as `user` or `key`) and in Reformat Code. It is **Off** by default: typing stays as typed and Reformat Code keeps writing keywords in upper case ([Settings](docs/settings.md#keyword-case-and-reformat-code)).
- **TUI: Reformat Code** (`⌥⇧F`, or ⌃k › Reformat Code) lays out the selection or the statement at the cursor as the GUI's `⌘⌥l` does, with the same formatter; `⌃u` undoes it in one step. A `keymap.json` that already gives `⌥⇧F` to another command keeps it: Reformat Code then has no key, and the status line says so at startup and how to give it one (`F1`) (#105).
- **Edit console results from joins, per table** (#102, GUI and TUI): a join's columns are edited in their own table when it is a base table whose whole primary key is in the result, as in DataGrip; `select * from crm.voc vo left join public.users pu on vo.user_idx = pu.idx` edits `voc` and `users` rows alike. Each edited row and table is its own `UPDATE <table> SET … WHERE <key> = …` through the same Submit (exactly one row each, read-only data sources, the Production question and log with undo SQL). Columns of a table whose key isn't in the result, computed columns, views and temporary tables stay read-only: the GUI dims their header with 🔒 and says why on hover (TUI: the status line on an edit key). The outer side of an outer join where no row matched is read-only in that row; a table joined with itself is edited per occurrence, by that occurrence's key (`alias.column`); columns with the same name (`idx`, `status`) go to their own table, never by name. Rows can't be added, cloned or deleted in a join. PostgreSQL ties each column to its table by the server's column origins, MySQL by the select list (a bare `*` with `USING` / `NATURAL` stays read-only there). See [Safety › Editing a join's result](docs/safety.md).
- **A pending-transaction badge and an idle reminder** (#106, GUI and TUI): a console with an open transaction shows **● Transaction pending** beside Commit / Roll back (red on Production; the TUI's title says it, with the keys), and Commit / Roll back show for a `BEGIN` typed in Auto mode too. A Production transaction left without a statement for 5 minutes is reminded about once in the console's Output and the status bar (one where nothing was changed says so, and that it still keeps its locks), with the server's own limit when it has one (PostgreSQL `idle_in_transaction_session_timeout`, MySQL `wait_timeout`) and keep-alive doesn't restart that limit's clock.

### Changed

- **Grid edits go into the query history** (GUI, TUI): what Submit ran from a result or a table tab (a join's per-table `UPDATE`s too) is listed in Query History like a console's run.
- **Completion offers only the words that can come next** after a keyword with a fixed follower (GUI, TUI): `left j` lists `join` (not `json_agg` …), `order` → `by`, `is` → `null` / `not null` …, `insert` → `into`, `union` → `select` / `all` / `distinct` ([Console completion](docs/database-tools.md#console-completion-postgresql-mysql)).
- **MCP never writes to a Production data source**: Read & write is greyed out for Production (as for Read-only) in the GUI, the TUI form saves it as read, and `qurry-mcp --allow-write` keeps such a source at Read even if its settings say write. An AI tool's change would skip the row-count confirm the app asks a person ([MCP server](docs/mcp.md)).
- **Completion lists in a new order**: at a statement start only statement keywords and templates come (typing `se` on a new line lists `select` and `set`, no longer the columns of the statement above), columns only where a column fits and only from the caret's statement, and functions come right after the columns. To see a column where none is listed, type the clause first (`select`, `where`, `on` …) or press `⌃Space` after it. In the TUI, `⌥↩` on an underlined unknown name now lists its fixes; anywhere else it still runs (`F5` and `⌃↩` always do).
- **TUI: typed quotes and brackets close themselves** (#105). Typing `(` now gives `()` with the caret between; nothing needs undoing: type the `)` as before and it steps over the one already there, and `⌫` right after the `(` removes both. A quote right after a letter (`it's`) and anything typed in a string or a comment go in alone.
- **Reformat Code (`⌘⌥l`) without a selection lays out the statement at the caret**, not the whole console, as the TUI does (#105). Select all first (`⌘a`) to reformat everything. It now uses the formatter the TUI shares, so some layouts differ slightly from before; strings, `E'…'` and `$$…$$` bodies, comments and quoted names stay as written.
- **The theme is one setting for the GUI and the TUI** (#103), in `settings.json` with the custom themes. On the first start of 0.3.2 the GUI moves the theme it kept inside the app there, unless the TUI had saved one, which then wins for both; if that fails, the status bar says so and the theme stays for that run (pick it again in Settings › Appearance to keep it). The TUI's **Auto** is now **Sync with OS** (by `COLORFGBG`, the GUI's dark or light pick); its saved Auto, Dark or Light stays until a theme is picked. Dracula, One Dark, Solarized and custom themes draw their own background in the TUI; Dark, Light and High contrast keep the terminal's. In truecolor the TUI's Red (Production) and Green Data Source rows and tabs, NULLs and grid ranges take the theme's colors, as the GUI's do. Until a theme is picked the GUI draws Dark and the TUI Sync with OS. **Dark, Light and High contrast changed slightly** where they missed the contrast minimum: text on the accent (primary buttons, High contrast's text there is now black), the Production stripe, Dark's dim text and NULL gray, Light's accent and link blue, its NULL gray, Production and Green tints and its error red; the TUI's warning yellow is now the GUI's.
- **Redis browser** (#108, GUI and TUI): the Database Explorer lists a Redis data source's databases with their key counts and no key tree; keys are browsed in the Redis tab, now **one per data source**, with a database picker (`db0 · 500 keys`; TUI `d`) and a key filter (SCAN pattern). A click on a database in the explorer switches the open tab. Folder key counts sit beside the folder name, the TTL column shows only key TTLs (`1d 4h`, `—` without expiry). The **Config** tab is greyed out, with a tooltip saying why and where the settings are, where the server refuses `CONFIG` (AWS ElastiCache / MemoryDB, Azure Cache, GCP Memorystore, Upstash …; checked once on connect). The **Terminal** (TUI `:`) completes commands with their arguments from a bundled command table and key names from a bounded SCAN, has ↑↓ history per data source (passwords in `AUTH`, `HELLO … AUTH`, `CONFIG SET requirepass`, `ACL SETUSER … >password` and `MIGRATE … AUTH` masked, quoted ones too; key names go in quoted when they need it, and `↩` on a key typed out runs the line, `⇥` picks), `HELP <command>`, and shows replies by type (a hash as a field / value table, a list numbered, sorted sets with scores). It follows the console's rules: a read-only data source runs read commands only (an unknown command counts as a write), **Production asks before a write**, and `FLUSHALL` / `FLUSHDB` / `DEL` always ask. After the update: a workspace with several Redis tabs of one data source reopens one tab on the database saved last; pick another database in its toolbar (TUI `d`) or click it in the explorer.
- **Production Redis consoles ask before writes only** (GUI and TUI): a read such as `GET` or `HGETALL` now runs without the Production question, as in the Terminal; writes, unknown commands and `FLUSHALL` / `FLUSHDB` / `DEL` still ask (#108).
- **A saved SSH host with a `Host` block in `~/.ssh/config` uses it**, as `ssh` does: its `HostName`, `ProxyJump`, `IdentityFile`, and `User` / `Port` when the data source leaves them empty / at 22. A `ProxyCommand` there now stops the connect, naming the file, line and `Host` block, with what to do (use `ProxyJump`, or `ProxyCommand none` in a narrower `Host` block above it). **A `ProxyCommand` under `Host *` stops every SSH tunnel it matches**, including data sources with their own key or password: add `Host <your-bastion>` / `ProxyCommand none` above it. An `IdentityFile` with a `%` token Qurry doesn't know (`%C`, `%n`, …) is skipped, not an error (#59).
- **PostgreSQL `~/.pgpass`** is matched against the data source's own host, port, database and user (it used to be matched against `PGHOST` / localhost) and is read only when no one else can read it (`chmod 600 ~/.pgpass`), as `psql` does; when it was skipped and the login fails, the error says why. **`PGSSLMODE` no longer overrides a data source's TLS mode** (a local or tunneled PostgreSQL source without SSL settings uses prefer, a remote one require, as the data source says). **`PGPASSWORD` is no longer sent to saved PostgreSQL data sources** without a saved password (GUI, TUI, MCP): an environment password goes only to a `qurry-tui` URL's server. If you relied on it, save the password in the data source or add a `~/.pgpass` line; the login error says so (#59).
- **Run and stop are one button** (#107): the console toolbar's ▶ turns into ■ in the same spot while it runs a statement, and a result grid's ↻ turns into ■ while it loads, also while it loads more rows on scroll (that ■ stops only the rows on their way; the rows shown stay). The status bar no longer has its own ▶ ■ buttons: it shows what the focused tab is doing and for how long — hover it for a ✕ that cancels — and `⌘↩`, `⌘F2` and the palette commands work as before. Its position reads `Ln 2, Col 11` (and `(8 chars)` for a selection) instead of `2:11`; a focused result grid shows its cell as `Row 3, Col 5` and, when not every column fits, the ones in view (`cols 3–8 of 14`). TUI: the console's title has **[▶ Run]**, which is **[■ Cancel]** while it runs, and a result wider than the window shows the columns in view on its bottom border — a heavier stretch of the line and `◀ cols 3–8 of 14 ▶` at its right end — instead of a bright block.
- **Production consoles start in Tx: Manual** (#106, GUI and TUI): a change stays pending until you Commit or Roll back, and closing the tab, switching the database or quitting asks first. A plain read (no row locks, no side-effect call) before the first change runs as in Auto, in a transaction that ends with it, so reading Production holds no snapshot or table locks (an `ALTER TABLE` doesn't wait behind it) and shows nothing pending; the transaction opens at the first other statement, or at a `BEGIN` you type. Such a read runs read-only: a function in it that writes is refused, nothing is changed, and the error says to run `BEGIN` first. This also applies to Production data sources whose Transaction control was already Manual. Redis and driver plugin consoles (SQLite, SQL Server, Oracle, ClickHouse, DuckDB …) can't be in Manual and start in Auto. The first such console of a data source says so once, and where to turn it off. **After the update**, if you relied on Tx: Auto committing at once on Production, press Commit, or turn off **Production: start consoles in Manual transaction mode** in Data Source Properties › Options (TUI: the data source form's `Production Manual`); new consoles then start in the Transaction control mode again. It is on for every Production data source, including ones saved before; an older Qurry (e.g. a Homebrew TUI that lags the app) that saves the data source turns it back on. Restored consoles (GUI and TUI) start in the data source's mode, like new ones. MCP's writes don't change: each still runs in a transaction of its own.
- **Grid edits in Manual mode or an open transaction run in it** (#106): a console result's Submit used to be refused there ("Read-only in a transaction"); it now runs the edits in the console's transaction under a savepoint (one that fails or doesn't change exactly one row undoes only that Submit) and they stay pending until Commit / Roll back, logged as not committed on Production. Results that were editable stay editable.

### Fixed

- **Console colors every statement word as a keyword**: PostgreSQL consoles showed `UPDATE`, `SET`, `INSERT`, `DELETE`, `VALUES`, `ALTER`, `DROP`, `BEGIN`, `COMMIT` … as plain names (the editor's grammar knew only reserved words), MySQL consoles `BEGIN`, `COMMIT`, `ROLLBACK`, `TRUNCATE` ….
- **Grid column headers stay over their columns when scrolled sideways**: in the app the headers sat one row-number width left of their columns (the header's row-number corner didn't stay put); the corner now sits beside the scrolled header.
- **PostgreSQL consoles drew strings in pure red and functions in magenta** (`'x'` as `#FF0000`, `upper` as `#FF00FF`) in every theme: they now take the theme's string and function colors, as in MySQL consoles (#103).
- **SSH / AWS SSM tunnel that stopped forwarding** (#110): after sleep or a network change, a query, a new connect or a console that sat unused no longer hangs: Qurry finds the dead tunnel, opens a new one and tries once more, and the errors name the way they went (SSM instance, SSH server or direct). An open transaction is never lost silently: a console whose transaction went with a closed tunnel, or with Disconnect, says so once and sends nothing, and a console whose session is only slow while the tunnel answers keeps its transaction. A running export, import, backup or restore keeps its tunnel and connections from being taken for dead or idle. The status line says why a data source was disconnected, with its name ([Data sources](docs/data-sources.md)).
- **The status bar's position followed the console editor only** (#107): it kept the editor's last `2:11` while a table tab, a result grid or the explorer had focus. It now shows the editor's position only while the editor has focus, the grid's cell while a grid has it, and nothing otherwise.
- **Add Row, then scrolling to it loaded more rows** (GUI and TUI): the loaded rows came after the new one in the TUI, so Revert dropped the loaded rows and Submit inserted them again; in the GUI the selection stayed where the new row had been, so Delete Row or Revert Selected hit a loaded row. Loaded rows now go before the added ones, and the selection, the cell being edited and the Value Editor's draft move with them. In the TUI also with the on-screen sort (`s`) on: the added rows stay last, and edited and deleted rows keep their edits when the sort changes.
- **A transaction the server ended because it sat idle** (PostgreSQL `idle_in_transaction_session_timeout`, MySQL `wait_timeout`) now says so by name on the next statement or Commit, and that it was rolled back (Commit no longer says its outcome is unknown); the Production log records "ROLLBACK (by the server)" (#106).

## [0.3.1] - 2026-11-04

### Added

- **Edit console results**: a console result from one table that includes the table's whole primary key edits like a table tab, in the GUI and the TUI: the same Submit path (each `UPDATE` / `DELETE` must hit exactly one row, read-only data sources, Production log), SQL written with the table's column names behind aliases. Joins, `GROUP BY`, `DISTINCT`, `UNION`, computed columns, views and results without the key stay read-only, and the greyed-out buttons (TUI: the status line) say why. Results of a temporary table or a locking read (`FOR UPDATE` / `FOR SHARE`, `LOCK IN SHARE MODE`), and every console result in Manual mode or while a transaction is open, stay read-only with the reason, because the edits are saved on a connection of their own. Running the console again with pending edits asks first (#86, [Getting started](docs/getting-started.md)).
- **Multi-select in the result grid**: ⌘-click adds a cell, a row (row number) or a column (header) to the selection, ⇧-click extends the last range; copy, the Data Extractor, Delete Row, Revert Selected and Set NULL act on every range. TUI: `m` marks the current row, `y` / `d` / `Y` act on the marked rows (#96).
- **Multi-select in the Database Explorer**: ⌘-click and ⇧-click select several nodes; Go to DDL, Edit Data, Copy Name / Reference, Refresh and **Drop…** (one confirmation, the Production one on Production sources) act on all of them. TUI: `m` marks nodes, Delete drops the marked objects. On MySQL, Drop… of several objects runs one statement per object, dependents first (a table before the tables it references), and a failure reports what was applied, what failed and what didn't run (#96, [Shortcuts](docs/shortcuts-gui.md)).
- **Console gutter marks**: each statement that ran is marked on its first line: ✓ done, ✗ failed, a spinner (TUI `…`) while it runs. Hover shows when it ran and its result or error; a click shows its line in Output. Only the latest run is marked: a new run clears the earlier marks, and editing the statement drops its mark (#98).
- **Completion in the table filter**: a table tab's WHERE / ORDER BY field completes like the console with the table's columns, keywords and functions (no other tables or schemas), as you type or with ⌃Space (TUI ⇥) (#93).
- **TUI light theme**: a light palette for light terminals and **⌃k › Theme…** (Auto, Dark, Light, saved in `settings.json`). Auto follows `COLORFGBG` and says at startup how to get the dark colors back (#90, [TUI in your terminal](docs/tui.md)).
- **Database Admin reports: pick the database** in the report toolbar (TUI: `d`) to rerun the report on it; like the console's database picker it lists every database of the server, the current one first (Manage Shown Schemas only filters the explorer). A connect error names the database and suggests picking another one only when the server refuses that database (#99, [Database tools](docs/database-tools.md)).
- **Add Font File…** in GUI **Settings › Editor / Grid font**: pick a `.ttf`, `.otf`, `.woff` or `.woff2` (up to 20 MB); Qurry copies it into its config folder and lists it as an added font you can remove. The TUI keeps the terminal's font (#87, [Settings](docs/settings.md)).

### Changed

- **`NULL` sits where its column's type does** in result grids (GUI and TUI): on the left in text, date / time, boolean and JSON columns, on the right in numeric ones; in a column without a type (a SQLite expression, MongoDB) it goes by the column's values. It is the new **Column type** choice for NULL in **Settings › Appearance › Alignment** (TUI **⌃k › Grid Alignment…**), and the default. A NULL alignment you saved as Left or Center stays as it was. If you kept the 0.3.0 default, `NULL`s in text-like columns move to the left: to keep the 0.3.0 look, set **NULL** to **Right** (#95, [Settings](docs/settings.md)).
- **⌘-click adds to the selection** in the result grid and the Database Explorer (it used to select only the clicked cell or node) (#96).
- **Submit on a Production data source asks first**, in table tabs as well as consoles: the dialog lists the statements; Cancel keeps the pending edits (#86).
- **Settings and Keymap Reference buttons** moved from the right end of the status bar to the bottom of the workspace rail on the far left; the workspace list scrolls above them. ⌘, and ⇧⌘/ still work. In maximized mode (tool windows hidden) there are no mouse buttons for them: use ⌘, / ⇧⌘/ or the Help menu (#97).
- **TUI Auto theme follows `COLORFGBG`**: on a terminal that reports a light background the TUI now draws its light palette. To keep the dark colors, pick **⌃k › Theme… › Dark** (#90).
- Console line numbers move to the right to make room for the gutter marks (#98).
- The running indicator moved from a card over the result to the status bar; ■ cancels runs and load-more (the card's Cancel button is gone). Loading more rows shows there too, as a run does ("Loading more rows…" with the elapsed time), so nothing covers the grid's rows; a load-more that fails says why beside the row count with **Run again**. TUI: the status line shows a moving bar, what runs or loads and the elapsed time, and the Cancel key stops a load-more too (#94).
- Release builds are faster: e2e runs one job per browser with two Playwright workers, and the release builds the CLI in its own job (#88).
- [SECURITY.md](SECURITY.md) describes the release signing key: where it lives, how it is rotated through a bridge release, and what happens when it is lost or leaked (#91).

### Fixed

- The database pickers of consoles, Redis browsers and Database Admin reports (and the console's schema picker) list their databases as soon as the tab is shown: the first click used to open a list with only the current database, the rest arriving too late.
- Console completion no longer offers column values in a JOIN's `ON` condition (`on m.admin_user_idx = `), where the other side is usually a column: the statement's columns complete there; a `WHERE` after the join still suggests values.
- Database Admin reports: picking a database the account can't connect to no longer makes the database list as wide as the window or empties it. The listing error shows above the report (and as the list's tooltip) instead of as a list entry, and the list is read through the source's default database when the report's refuses, so another one can be picked (TUI `d` likewise). Long database names are cut with … in the report's and the console's lists.
- **Statements popup** (⌘↩ with several choices; TUI F5): while a choice is highlighted the editor highlights exactly what it would run (TUI: its rows; the TUI chooser sits at the bottom so they stay in view), and the highlight goes when the popup closes. The GUI popup now has the keys like a menu: ↑↓ and Enter pick, Esc or any other key closes it without running and without typing into the editor, a click outside or focus leaving closes it, and the caret is where it was.
- **New Query Console** (⇧⌘L) and the other commands that act on the explorer selection use the shown workspace's selection: back from a workspace with a Redis source selected, a new console used to open for that Redis source, and every new console after it.
- Console Output keeps its newest line in view while following: new lines, long wrapped lines (TUI) and a pane made shorter or narrower (#92).
- **Manage Shown Schemas**: with **All databases** or **All schemas** on, unchecking one database or schema used to do nothing until All was unchecked first. Now All turns off and the other listed ones stay shown (a database keeps its schema choice; system schemas and MySQL's system databases stay hidden unless checked one by one); checking every one again turns All back on (GUI and TUI, as in DataGrip). The Schemas tab of Data Source Properties follows the same rules: under All, every database and schema shows checked.

Qurry runs the AWS CLI v2 and its Session Manager plugin and stores no AWS secrets. Host and Port are the database as seen from the instance (the form hints when they point at the instance itself); Qurry ends its sessions on the AWS side when it closes them. Update every Qurry app on the computer first: older ones don't know the tunnel ([Data sources](docs/data-sources.md)).

### Changed

- **`NULL` is right-aligned** in result grids (GUI and TUI), so a `NULL` in a numeric column lines up with its numbers. To have it on the left as before, set **Settings › Appearance › Alignment › NULL** to **Left**. Numbers the driver sends as text (`numeric`, large `bigint`) are now right-aligned in the GUI too, as the TUI did (#75).

- **Releases**: a merge to `main` now publishes a beta pre-release (`vX.Y.Z-beta.N`). Stable releases come only from a version tag on `main`, and only they update Homebrew. Only the 20 newest betas keep their release page: an older beta can't install driver plugins any more and says to update Qurry. A beta `.deb` has the package version `X.Y.Z~beta.N`, so `apt` takes the stable `X.Y.Z` as an upgrade.
- **macOS 13 Ventura or later** is needed for the GUI. On macOS 12 or older keep Qurry 0.2.x; the TUI and the MCP server still run there ([what to do if an update already went through](docs/updates.md#macos-12-and-older)).
- The GUI and the TUI share one Rust core for statement splitting, the Production guard, completion, grid copy formats, charts and the keymap. The GUI runs it as WebAssembly, so its Content Security Policy allows `wasm-unsafe-eval`.
- The GUI Production confirmation decides like the TUI: a keyword inside a string, a quoted name or a MySQL `#` comment no longer asks. Settings under which a statement could write, side-effect functions (`nextval`, `setval`, `dblink_exec`, `lo_*`) and `SELECT … INTO` now ask. A selection run as one statement is a read only if every statement in it is (`select 1; do $$ … delete … $$` asks), and so is SQL Server text that starts another statement without `;`.
- **Explain Analyze** asks first when a rollback can't undo what the statement does (sequence values, `dblink_exec`, `SELECT … INTO OUTFILE`, a `COMMIT` or MySQL DDL after the first statement): Cancel runs nothing, and Output says afterwards what stays. On data sources other than PostgreSQL and MySQL it isn't wrapped in a transaction and asks "it changes data". GUI and TUI decide the same way ([Safety](docs/safety.md)).
- GUI console: while the WebAssembly module loads, `⌘↩` shows a loading bar and runs once it arrives. Without the module, a notice says once when a console opens that autocomplete is off.
- PostgreSQL strings with a backslash are written as `E'…'` in grid copy formats, **Filter by** and the SQL of grid edits (they used to write `'a\b'`), and MySQL value hints double backslashes. ClickHouse names in the grid's SQL double a backslash inside the quotes, as the server reads them.
- Errors for operations a driver plugin doesn't support read "<op> isn't available for the <driver> driver".
- **Explain Analyze** on PostgreSQL and MySQL rolls back every statement, reads included (a function a `SELECT` calls could write), and asks first before an `UPDATE` or `DELETE` without `WHERE` (every row stays locked until the rollback). Inside an open transaction (on MySQL also one Qurry didn't see open, such as a `START TRANSACTION` inside a `/*! … */` comment), or on MySQL with autocommit off however it was switched off, it uses a savepoint, so it never commits work you left uncommitted. It asks that one question instead of the "dangerous statement" question as well, in the GUI as in the TUI. On a read-only data source it works inside a transaction you opened.
- Contributors need the `wasm32-unknown-unknown` target and `wasm-bindgen-cli` 0.2.129 ([Development](docs/development.md)).

### Fixed

- GUI result grid, table data editor and transposed view: rows no longer show through a strip between the toolbar and the column header in a short result panel on macOS (#82).
- PostgreSQL nested comments and MySQL `#` comments split the way the server reads them, so a commented-out statement never runs.
- Full-text search runs each table's `SELECT` in a READ ONLY transaction on PostgreSQL and MySQL, so a view whose function writes (an `INSERT`, `nextval`) is refused instead of committed.
- Console completion: quoted names with spaces before the dot, `from sales.` with a table named `sales`, Korean identifiers, and long scripts stay fast.
- Korean names rank like their ASCII twins in the TUI palette and MCP `search_objects`; Redis key folders stop at 64 levels.
- Database Admin reports on managed services, MariaDB and large servers (#64); a failed refresh keeps the last result and says how old it is.
- MySQL backup and restore: the client that matches the server's kind and version, `--set-gtid-purged=OFF`, optional removal of `DEFINER=` clauses, and shell commands off during a restore.
- Production log: a change is logged before it runs, and undo SQL is kept only when every changed row was saved.
- PostgreSQL full-text search and value hints write a search text or value with a backslash as `E'…'`, so a server with `standard_conforming_strings = off` can't read it as SQL.
- SQL Server: a `SELECT` of columns named `open`, `close` and the like is a read again (no Production confirmation).
- TUI: the Explain Analyze note about what a rollback can't undo is a warning, not an error.
